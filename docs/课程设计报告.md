# 操作系统课程设计报告

## 1. 项目概述

本项目实现了一个操作系统原型模拟器 OS_SIM_CPP。系统以 C++ 为主要开发语言，通过进程管理、内存管理、文件系统、磁盘管理、设备管理和 IPC 模块，模拟操作系统中资源管理和进程运行的核心过程。

项目采用模块化设计。底层由磁盘、内存、进程、文件系统、设备和 IPC 模块组成；上层由命令解释器和 Web 前端组成。用户可以通过浏览器页面或命令接口创建进程、切换调度算法、访问内存、操作文件、申请设备和进行进程通信。

## 2. 需求分析

课程设计要求在 PC 上实现一个操作系统原型，通常包括进程管理、内存管理、文件管理等部分，并能够展示系统运行过程、各进程状态和相关参数变化。

结合课程要求，本项目的目标如下：

- 实现进程的创建、撤销、阻塞、唤醒、挂起、恢复和终止。
- 使用 PCB 描述进程，并展示进程队列状态。
- 实现至少一种调度算法，并支持多进程竞争 CPU、内存和 I/O 设备。
- 实现一种内存管理方式，并展示内存分配、缺页和页面置换过程。
- 实现简单文件系统，支持文件和目录操作。
- 将各模块集成为一个小型操作系统模拟器。
- 提供源代码、可执行程序、测试结果、设计文档和演示流程。

## 3. 系统总体设计

系统主要由以下模块组成：

```text
Web 前端 / 命令行
        |
HTTP API 与命令解释器
        |
进程管理 ---- 内存管理/MMU ---- 磁盘管理
   |              |              |
设备管理/IPC     页面置换       文件系统
```

### 3.1 进程管理模块

进程管理模块维护全局 PCB 表和多个进程队列。PCB 中包含 PID、进程名、状态、优先级、动态优先级、时间片、内存需求、到达时间、剩余运行时间、等待时间、阻塞时间、周转时间、父进程和子进程等信息。

支持的进程状态包括：

- READY：就绪。
- RUN：运行。
- BLOCK：阻塞。
- END：结束。
- SUSPEND：挂起。
- ZOMBIE：僵尸。

支持的调度算法包括：

- Dynamic Priority + RR：动态优先级与时间片轮转结合。
- SJF：短作业优先。
- FCFS：先来先服务。
- HRRN：高响应比优先。

### 3.2 内存管理模块

内存模块采用分页式虚拟内存设计。每个进程拥有逻辑页表空间，系统维护页目录、页表项、物理页框状态和 TLB。

核心机制包括：

- 逻辑地址到物理帧和页内偏移的转换。
- 缺页中断处理。
- 页面装入和置换。
- FIFO、LRU、CLOCK 页面置换策略。
- 内存访问统计。
- 后台监控线程输出内存使用情况。
- 共享内存映射。
- 进程内存动态扩缩容。

### 3.3 磁盘管理模块

磁盘模块使用 `vdisk.bin` 模拟物理磁盘。磁盘被划分为固定大小的数据块，并维护 inode 位图、数据块位图和 inode 表。

核心能力包括：

- 磁盘格式化。
- 数据块分配和释放。
- inode 分配和释放。
- inode 读写。
- 数据块读写。
- 关闭系统时同步磁盘数据。

### 3.4 文件系统模块

文件系统基于磁盘模块实现，使用 inode 记录文件元数据。目录以目录项形式保存文件名和 inode 编号。

支持的功能包括：

- 文件创建和删除。
- 目录创建和删除。
- 文件读写。
- 按偏移读写。
- 文件权限修改。
- inode 信息查看。
- 目录切换、列表和树形展示。
- 文件重命名、复制、搜索和打包。

### 3.5 设备管理与 IPC 模块

设备管理模块模拟打印机、键盘、磁盘等 I/O 设备。系统维护设备占用状态、等待队列，并使用银行家算法进行资源安全性检查，降低死锁风险。

IPC 模块支持：

- 信号量创建。
- P 操作和 V 操作。
- 进程消息发送和读取。
- 进程阻塞与唤醒联动。

### 3.6 前端和命令交互

系统通过 `httplib.h` 启动 HTTP 服务，监听 `8080` 端口。前端页面调用 API 完成开机、状态刷新、命令执行、文件查看和编辑等操作。

主要 API 包括：

- `POST /api/boot`
- `GET /api/status`
- `GET /api/files`
- `GET /api/file/<name>`
- `POST /api/command`

## 4. 关键算法

### 4.1 动态优先级 + 时间片轮转

系统根据动态优先级从就绪队列中选择进程。进程等待时间增加时，动态优先级会逐步提升，避免长期饥饿。进程时间片用完后让出 CPU，并重新进入就绪队列。

优点：

- 能兼顾优先级和公平性。
- 通过老化机制降低低优先级进程长期等待的风险。
- 适合演示进程队列迁移和时间片调度。

缺点：

- 参数较多，需要合理设置老化阈值和时间片长度。
- 调度过程比 FCFS 更复杂。

### 4.2 SJF

短作业优先根据剩余运行时间选择进程。

优点：

- 平均等待时间通常较短。

缺点：

- 长作业可能等待较久。
- 需要知道或估计运行时间。

### 4.3 FCFS

先来先服务按照到达顺序调度进程。

优点：

- 实现简单，便于解释。

缺点：

- 容易出现长作业阻塞短作业的情况。

### 4.4 HRRN

高响应比优先综合等待时间和服务时间选择进程。

优点：

- 兼顾短作业和长作业。
- 等待时间越长响应比越高，可缓解饥饿。

缺点：

- 每次调度都需要计算响应比。

### 4.5 页面置换算法

系统支持 FIFO、LRU 和 CLOCK。

FIFO 按页面进入内存的顺序置换，简单直观，但可能出现 Belady 异常。LRU 根据最近使用情况置换，更符合局部性原理，但维护成本更高。CLOCK 使用引用位近似 LRU，在效率和效果之间折中。

## 5. 实验模拟结果

### 5.1 文件系统测试

`run_fs_test` 覆盖目录操作、文件创建、文件读写、重命名、只读权限、大文件跨块分配、截断和清理。测试通过，说明文件系统能够正确调用磁盘模块完成 inode 和数据块操作。

### 5.2 磁盘与内存测试

`os_sim_test_disk_memory` 创建进程逻辑页表并连续访问 10 个逻辑页。首次访问触发缺页中断，并将页面装入物理帧。测试结果中合法访问 10 次、缺页 10 次、非法访问 0 次，说明缺页处理和页面装入流程正常。

### 5.3 主程序编译测试

主程序在 Cygwin g++ 环境下使用 `-D_DEFAULT_SOURCE` 可编译通过。该宏用于保证 `httplib.h` 依赖的 socket 和 addrinfo 等声明可见。

## 6. 结果分析

本项目覆盖了课程要求中的三个核心部分：进程管理、内存管理和文件管理，并进一步实现了磁盘持久化、设备管理、IPC 和前端演示。

进程模块能够展示 PCB、队列迁移和调度算法变化。内存模块能够展示虚拟内存访问、缺页中断和页面置换。文件系统能够展示目录、文件、inode、权限和持久化。各模块通过命令解释器和 Web 前端集成，能够形成完整演示流程。

不足之处：

- Web 服务退出流程在异常终止时可能输出底层库断言信息，验收时应采用正常关闭方式。
- 前端 AI 和语音控制接口属于扩展能力，核心验收应重点展示稳定的命令和状态面板。
- 目前测试主要集中在文件、磁盘和内存，进程调度、设备和 IPC 的自动化测试还可以继续加强。

## 7. 难点

- 多模块接口协调：进程创建需要申请内存，进程终止需要释放内存和设备，文件系统需要依赖磁盘持久化。
- 虚拟内存实现：页表、TLB、缺页中断和页面置换之间存在较多状态同步。
- 文件系统持久化：需要保证 inode、目录项、数据块和位图之间一致。
- 统一演示：需要将分散模块接入命令行和前端，使验收时可以连续展示。

## 8. 验证问题

可通过以下问题验证系统功能：

- 创建多个进程后，是否可以查看 PCB 和各队列状态？
- 切换调度算法后，运行队列和统计结果是否发生变化？
- 阻塞、唤醒、挂起、恢复是否会引起队列迁移？
- 访问未装入页面时，是否触发缺页中断？
- 切换 FIFO/LRU/CLOCK 后，内存统计是否能显示当前策略？
- 创建文件并重启系统后，数据是否仍保存在虚拟磁盘中？
- 只读文件是否能阻止写入和删除？
- 设备被占用后，其他进程是否进入等待队列？
- 信号量 P/V 操作是否会阻塞和唤醒进程？

## 9. 结论

OS_SIM_CPP 已经实现一个可演示的小型操作系统原型。系统覆盖进程、内存、文件三大核心模块，并通过磁盘、设备、IPC、命令行和 Web 前端增强展示效果。项目能够满足课程设计对源代码、可执行程序、系统演示、测试和文档的基本要求。

后续可以继续补充进程调度、设备管理和 IPC 的自动化测试，并优化 Web 服务关闭流程，使系统在更多环境下运行更稳定。
