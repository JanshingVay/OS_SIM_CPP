# 会议纪要

## 第一次会议纪要

会议主题：确定课程设计方向、成员分工和整体目标。

会议内容：

- 明确项目目标：实现一个操作系统原型模拟器，覆盖进程管理、内存管理、文件管理，并扩展设备管理、IPC 和 Web 前端演示。
- 确定技术路线：采用 C++ 实现核心模块，使用虚拟磁盘文件保存文件系统数据，使用 HTTP 服务连接前端页面。
- 确定小组分工：
  - 侯博文负责文件系统、磁盘持久化调用、命令行交互、Vim 设计和前端界面优化。
  - 韦建兴负责磁盘模块和磁盘相关集成测试。
  - 崔敬哲负责内存管理和页面功能优化。
  - 徐舸山负责进程管理、进程命令、AI/语音接口、内存接口调用和 MMU。
  - 杨皓哲负责设备管理、前端和 IPC。
- 确定协作方式：各模块先独立实现，再通过主程序统一接入命令系统和前端。

存在问题：

- 模块之间接口较多，需要提前约定进程、内存、磁盘、文件系统之间的数据结构。
- 验收需要统一演示，不能只展示独立小程序。

解决方案：

- 以 `os_sim_main.cpp` 作为集成入口。
- 每个模块提供清晰的函数接口。
- 通过命令行和前端统一调用各模块能力。

## 第二次会议纪要

会议主题：中期集成检查和问题修正。

已完成内容：

- 进程模块完成 PCB、队列、调度算法和进程控制命令。
- 内存模块完成分页、页表、TLB、缺页中断和页面置换。
- 磁盘模块完成块读写、位图、inode 存取和格式化。
- 文件系统完成文件、目录、权限和读写操作。
- 设备和 IPC 模块完成设备请求、释放、信号量和消息通信。
- 前端完成基本展示、命令输入和状态刷新。

存在问题：

- 单独模块可以运行，但集成演示需要更清楚的流程。
- README 缺少完整说明。
- 测试结果没有整理成文档。
- 部分编译环境需要额外宏定义。

解决方案：

- 补充 README、课程设计报告、验收演示流程和测试结果。
- 将主程序编译命令统一为带 `-D_DEFAULT_SOURCE` 的版本。
- 将常用命令整理为演示脚本，减少现场操作风险。

## 周总结

### 第一阶段：需求分析与总体设计

完成课程设计要求分析，确定项目至少需要覆盖进程管理、内存管理、文件管理三个核心部分。小组决定在此基础上扩展设备管理、IPC 和 Web 前端，使项目更适合现场演示。

### 第二阶段：核心模块实现

各成员分别完成进程、内存、磁盘、文件系统、设备和 IPC 的核心功能。模块之间通过函数接口连接，进程模块能够调用内存接口，文件系统能够调用磁盘接口。

### 第三阶段：系统集成

通过 `os_sim_main.cpp` 将各模块集成到统一命令解释器，并通过 `httplib.h` 提供 HTTP API。前端页面调用 API 获取系统状态和执行命令。

### 第四阶段：测试与验收准备

完成文件系统测试、磁盘和内存集成测试、压力测试脚本设计。补充验收文档、成员分工、会议纪要、演示流程和测试结果。
