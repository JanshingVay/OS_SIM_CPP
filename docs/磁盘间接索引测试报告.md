## 1. 测试背景

磁盘模块最初仅支持 **直接索引**（iNode 中 `direct_blocks[10]`，最多寻址 10 个数据块 = 10KB）。本次改造在 iNode 大小保持 64 字节的前提下，新增了 **一级间接索引** 和 **二级间接索引**，对标真实文件系统（如 ext2/ext3）的索引结构。

### iNode 结构变更

```
旧布局: i_num(4) + i_mode(4) + i_size(4) + is_readonly(4) + direct_blocks[10](40) + padding(8) = 64B
新布局: i_num(4) + i_mode(4) + i_size(4) + is_readonly(4) + direct_blocks[10](40) + single_indirect(4) + double_indirect(4) = 64B
```

### 索引能力对比

| 索引级别 | 可寻址数据块数 | 可寻址容量 |
|---------|-------------|-----------|
| 仅直接索引（旧） | 10 | 10 KB |
| + 一级间接索引 | 10 + 256 = 266 | 266 KB |
| + 二级间接索引 | 10 + 256 + 65536 = 65802 | ~64 MB |

> 实际可用容量受 `TOTAL_BLOCKS = 10240`（10 MB 磁盘）的限制。

## 5. Bug 修复记录

| 编号 | 问题描述 | 修复方案 | 状态 |
|------|---------|---------|------|
| B1 | `read_inode` 对旧格式磁盘（padding 区为 0）不兼容，导致 `single_indirect` / `double_indirect` 被误读为 0 | 新增 `iNode::normalize()` 方法，在 `read_inode` 后调用，将 0 规范化为 -1 | ✔ 已修复 |
| B2 | `allocate_nth_block` 分配二级间接时，新分配的一级间接块未初始化为 -1，导致脏数据误判 | 修改二级间接分配逻辑：先分配一级间接块并初始化全 -1 数组，再在二级间接表中写入指针 | ✔ 已修复 |
| B3 | `filesystem.cpp` 的 `write_file` 和 `read_file` 仅支持 `block_idx < 10`（直接索引），无法利用间接索引 | 改用 `get_disk_manager().get_nth_block()` 和 `allocate_nth_block()` 替换直接访问数组 | ✔ 已修复 |

## 6. 新增 API 说明

### DiskManager 公开方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `get_nth_block` | `int get_nth_block(const iNode&, int n)` | 按逻辑块号 n 解析物理块 ID，自动穿越三级索引 |
| `allocate_nth_block` | `int allocate_nth_block(iNode&, int n)` | 确保第 n 个逻辑块存在，按需创建间接块 |
| `free_all_data_blocks` | `void free_all_data_blocks(iNode&)` | 递归释放 iNode 的全部数据块（直接+间接链） |

### DiskManager 私有方法

| 方法 | 说明 |
|------|------|
| `_alloc_indirect_data_block` | 在指定间接块的 idx 位置分配数据块 |
| `_free_single_indirect_chain` | 释放一级间接块及其指向的全部数据块 |
| `_free_double_indirect_chain` | 递归释放二级间接链 |
