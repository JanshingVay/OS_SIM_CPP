# 测试结果

## 测试环境

- 操作系统：Windows + Cygwin g++
- 编译器：g++
- 编译标准：C++11 / C++14
- 线程库：pthread

## 1. 文件系统与磁盘集成测试

编译命令：

```bash
g++ -O2 -std=c++11 test_fs.cpp filesystem.cpp disk.cpp -o run_fs_test -pthread
```

运行命令：

```bash
./run_fs_test
```

测试覆盖：

- 虚拟磁盘初始化和挂载。
- 根目录初始化。
- 目录创建、进入和返回。
- 文件创建、写入、读取和重命名。
- 只读权限控制。
- 大文件跨块分配。
- 文件截断和 inode 大小更新。
- 中间产物清理。

实测结果：

```text
所有集成测试均已通过。
```

结论：

文件系统能够通过磁盘模块完成数据块和 inode 操作，具备基本持久化能力，满足课程设计中文件管理部分的验收要求。

## 2. 磁盘与内存集成测试

编译命令：

```bash
g++ -O2 -std=c++11 \
    disk.cpp \
    memory/memory.cpp \
    test_disk_memory.cpp \
    -o os_sim_test_disk_memory \
    -pthread
```

运行命令：

```bash
./os_sim_test_disk_memory
```

测试覆盖：

- 进程逻辑页表空间创建。
- 连续访问逻辑页。
- 缺页中断触发。
- 页面装入物理帧。
- 内存访问统计。
- 后台内存跟踪线程输出。

实测结果摘要：

```text
合法逻辑页访问次数: 10
命中次数: 0
缺页次数: 10
非法访问(越界): 0
物理内存使用率: 10 / 32 页
```

结论：

内存模块能够完成逻辑页访问、缺页处理和物理页框状态跟踪，并能与磁盘模块协同工作。

## 3. 主程序编译测试

编译命令：

```bash
g++ -O2 -std=c++14 -D_DEFAULT_SOURCE \
    os_sim_main.cpp \
    memory/memory.cpp \
    process/program.cpp \
    process/device.cpp \
    process/ipc.cpp \
    filesystem.cpp \
    disk.cpp \
    -o os_simulator \
    -pthread
```

实测结果：

```text
编译通过。
```

说明：

在 Cygwin 环境中，如果不添加 `-D_DEFAULT_SOURCE`，`httplib.h` 可能无法正确识别 socket、addrinfo、timeval 等声明，导致编译失败。因此验收时建议使用本文档中的完整编译命令。

## 4. 进程、设备和 IPC 模块测试

编译命令：

```bash
g++ -O2 -std=c++14 -D_DEFAULT_SOURCE \
    test_process_ipc_device.cpp \
    memory/memory.cpp \
    process/program.cpp \
    process/device.cpp \
    process/ipc.cpp \
    disk.cpp \
    -o test_process_ipc_device_check \
    -pthread
```

运行命令：

```bash
./test_process_ipc_device_check
```

测试覆盖：

- 多进程创建和 PCB 状态。
- 四种调度算法切换。
- 阻塞、唤醒、挂起、恢复。
- fork、僵尸进程和 wait 回收。
- 进程动态内存扩容和逻辑地址访问。
- 信号量 P/V。
- 进程消息发送和读取。
- 设备申请、设备忙等待队列和资源释放。

预期结果：

```text
[OK] process/device/ipc unit test passed
```

结论：

该测试补齐了原先较弱的进程管理、设备管理和 IPC 自动化验证，能够证明核心状态迁移和模块联动可执行。

## 5. HTTP API 整体集成测试

运行方式：

```bash
./os_simulator
python3 test_api_integration.py --base-url http://127.0.0.1:8080/api
```

或直接执行：

```bash
bash run_all_tests.sh
```

测试覆盖：

- `/api/boot` 启动系统。
- `/api/status` 查询系统状态。
- `/api/command` 执行进程、内存、文件、设备和 IPC 命令。
- 创建进程后从状态接口确认进程存在。
- 阻塞/唤醒、挂起/恢复后确认队列变化。
- 切换调度算法和页面置换算法。
- 创建文件、写入内容、读取内容、修改权限。
- 信号量和消息通信。
- 设备状态查询。

预期结果：

```text
[OK] API integration test passed
```

结论：

整体集成测试能够证明系统不是只靠单模块运行，而是可以通过主服务和前端同源 API 连续调度各模块，符合期末验收的综合演示需求。

## 6. 一键测试脚本

脚本：

```bash
bash run_all_tests.sh
```

执行内容：

- 编译并运行文件系统与磁盘测试。
- 编译并运行磁盘与内存测试。
- 编译并运行进程、设备、IPC 测试。
- 编译主程序。
- 启动主程序并执行 HTTP API 集成测试。

预期结果：

```text
==> All tests passed
```

## 7. 压力测试设计

脚本：

```bash
python3 test_os_pressure.py
```

测试目标：

- 并发发送创建进程命令。
- 并发发送 I/O 设备申请命令。
- 观察进程队列、内存回收、设备等待队列和死锁避免情况。

注意：

压力测试需要先启动 `os_simulator`，并保证服务监听在 `http://localhost:8080`。
