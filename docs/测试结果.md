# 测试结果

## 测试环境

- 操作系统：Windows + Cygwin g++
- 编译器：g++
- 编译标准：C++11 / C++14
- 线程库：pthread

## 1. 文件系统与磁盘集成测试

编译命令：

```bash
g++ -O2 -std=c++11 test_fs.cpp filesystem.cpp disk.cpp -o run_fs_test -pthread
```

运行命令：

```bash
./run_fs_test
```

测试覆盖：

- 虚拟磁盘初始化和挂载。
- 根目录初始化。
- 目录创建、进入和返回。
- 文件创建、写入、读取和重命名。
- 只读权限控制。
- 大文件跨块分配。
- 文件截断和 inode 大小更新。
- 中间产物清理。

实测结果：

```text
所有集成测试均已通过。
```

结论：

文件系统能够通过磁盘模块完成数据块和 inode 操作，具备基本持久化能力，满足课程设计中文件管理部分的验收要求。

## 2. 磁盘与内存集成测试

编译命令：

```bash
g++ -O2 -std=c++11 \
    disk.cpp \
    memory/memory.cpp \
    test_disk_memory.cpp \
    -o os_sim_test_disk_memory \
    -pthread
```

运行命令：

```bash
./os_sim_test_disk_memory
```

测试覆盖：

- 进程逻辑页表空间创建。
- 连续访问逻辑页。
- 缺页中断触发。
- 页面装入物理帧。
- 内存访问统计。
- 后台内存跟踪线程输出。

实测结果摘要：

```text
合法逻辑页访问次数: 10
命中次数: 0
缺页次数: 10
非法访问(越界): 0
物理内存使用率: 10 / 32 页
```

结论：

内存模块能够完成逻辑页访问、缺页处理和物理页框状态跟踪，并能与磁盘模块协同工作。

## 3. 主程序编译测试

编译命令：

```bash
g++ -O2 -std=c++14 -D_DEFAULT_SOURCE \
    os_sim_main.cpp \
    memory/memory.cpp \
    process/program.cpp \
    process/device.cpp \
    process/ipc.cpp \
    filesystem.cpp \
    disk.cpp \
    -o os_simulator \
    -pthread
```

实测结果：

```text
编译通过。
```

说明：

在 Cygwin 环境中，如果不添加 `-D_DEFAULT_SOURCE`，`httplib.h` 可能无法正确识别 socket、addrinfo、timeval 等声明，导致编译失败。因此验收时建议使用本文档中的完整编译命令。

## 4. 压力测试设计

脚本：

```bash
python3 test_os_pressure.py
```

测试目标：

- 并发发送创建进程命令。
- 并发发送 I/O 设备申请命令。
- 观察进程队列、内存回收、设备等待队列和死锁避免情况。

注意：

压力测试需要先启动 `os_simulator`，并保证服务监听在 `http://localhost:8080`。
